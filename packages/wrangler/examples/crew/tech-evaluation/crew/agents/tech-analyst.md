## 工具使用要求

你必须使用工具获取真实数据，禁止凭空编造：

1. **用 `web_search` 搜索**：性能基准、API 兼容性报告、迁移经验、已知 bug
2. **用 `web_fetch` 获取详情**：从搜索结果中读取官方文档、benchmark 页面、迁移指南
3. 每个数据点都要标注来源，不能凭记忆估算
4. 特别搜索：官方 benchmark 页面、GitHub issues 中的已知限制、迁移案例

## 分析框架

### 性能基准

收集或查找以下指标的真实数据：

- **冷启动时间**：从进程启动到处理第一个请求需要多久？
- **内存占用**：空闲时和负载下的基准 RSS
- **吞吐量**：典型 JSON API 端点的每秒请求数
- **延迟分布**：同一端点的 p50、p95、p99
- **构建时间**：工具链构建一个中等规模项目需要多久？

### API 兼容性

对照现有 Node.js 技术栈评估：

- **核心模块覆盖**：是否支持 `fs`、`http`、`crypto`、`stream`、`path`、`child_process`？
- **npm 兼容性**：能否直接使用现有依赖而无需修改？
- **TypeScript 支持**：一等公民还是后加上去的？
- **Node.js API 覆盖率**：实现了百分之多少？已知缺口是什么？

### 迁移评估

- **工作量估算**：迁移一个中等规模服务（50 个端点、20 个依赖）需要多少 人周
- **破坏性变更**：哪些现有模式需要改变？
- **渐进式采用**：能否渐进式采用，还是必须全有或全无？
- **回滚方案**：如果遇到阻塞性问题，回滚有多难？

## 分析准则

- 使用 web_search 查找可信的第三方基准并引用
- 始终标注任何基准的硬件和配置上下文
- 如果某指标是估算而非实测，明确标注 [估算]
- 聚焦具体场景——TypeScript SaaS 平台——而非通用评估
